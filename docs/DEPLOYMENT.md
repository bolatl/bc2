# Бесплатная демонстрация Kintsugi для судей

Цель: судьи открывают HTTPS-ссылку и проходят весь продукт, включая демонстрационную оплату, без списания денег. После выбора тарифа пользователь подтверждает заранее заполненную форму тестовой карты и получает активную подписку. Для этого настроены `DISABLE_PAYWALL=false`, `VITE_PAYMENT_MODE=mock` и пустой `STRIPE_SECRET_KEY`. База данных не требуется — приложение использует память и локальный JSON-файл.

## Рекомендуемый вариант: Render Free

В корне проекта добавлен `render.yaml`: **один бесплатный Docker Web Service**, без платного диска, БД и Stripe. Dockerfile собирает React и Go в один образ; интерфейс и API работают на одном домене. Ссылка вида `https://your-service.onrender.com` подходит для отправки судьям, покупать домен не нужно.

Порядок запуска:

1. Добавьте изменения проекта в свой Git-репозиторий и отправьте их на GitHub. `.env`, `.env.deploy`, ключи и данные остаются локально.
2. В Render выберите **New → Blueprint**, подключите репозиторий и используйте `render.yaml`. Проверьте, что план сервиса — **Free**, платных ресурсов нет.
3. Для настоящих ответов Claude введите ключ в поле `LLM_API_KEY`, которое Render показывает при создании Blueprint. Если вы уже заполнили это поле, повторно добавлять ключ не нужно: Render сохранит его как переменную окружения сервиса. Проверить или заменить её можно в **сервис → Environment → Environment Variables**. Используйте действующий ключ, который не публиковался в чате или репозитории; ранее опубликованный ключ следует отозвать и заменить. Для полностью автономной демонстрации можно оставить поле пустым: будет работать offline mock.
4. `SESSION_SECRET` Render сгенерирует автоматически. Сервис берёт свой публичный адрес из `RENDER_EXTERNAL_URL`; вручную задавать `FRONTEND_URL`, `ALLOWED_ORIGINS` и `ADDR` не нужно. Явный `FRONTEND_URL` имеет приоритет, если позже понадобится другой домен.
5. Если используете Claude, задайте публичный `VITE_LLM_MODE=anthropic`; для mock — `mock`. Это подпись режима, а не ключ. Изменение `VITE_*` требует пересборки. По умолчанию стоит честное `unknown`.
6. После сборки откройте выданную ссылку и `/healthz`. Пройдите бесплатную подготовку A, выберите тариф и заполните демонстрационную форму карты по инструкции ниже. После активации плана завершите подготовку, откройте приглашение B в приватном окне и проверьте общий журнал. Затем передайте судьям ссылку на корень приложения.

Для Render не нужно загружать `.env` или `.env.deploy`: инструкции с этими файлами относятся к локальному запуску, туннелю или своему серверу. `LLM_API_KEY` — секретный ключ для серверных запросов, а `VITE_LLM_MODE=anthropic` — только публичная подпись в интерфейсе. Значение `unknown` у этой подписи не отключает Claude. Если меняете только ключ в уже созданном сервисе, выберите **Save and deploy**; если меняете `VITE_LLM_MODE`, нужна **Save, rebuild, and deploy**. Подробнее: [переменные окружения Render](https://render.com/docs/configure-environment-variables).

Render Free [засыпает после 15 минут без входящего трафика](https://render.com/docs/free). Первый запрос после сна запускает сервис заново; по документации это занимает около минуты. **Локальные файлы стираются при сне, перезапуске и новом деплое.** Это приемлемо для новой демонстрационной сессии, но не для хранения истории между оценками. В пределах работающего экземпляра JSON сохраняет данные. Перед защитой откройте приложение и убедитесь, что оно загрузилось; не делайте новый деплой во время оценки.

Если в браузере осталось старое состояние после сброса сервера, начните заново или откройте приватное окно. Тестовые данные не нужно добавлять в Git.

## Настройки бесплатного демо

| Переменная | Значение |
| --- | --- |
| `APP_ENV` | `production` — HTTPS и проверки безопасной конфигурации остаются включены |
| `COOKIE_SECURE` | `true` |
| `SESSION_SECRET` | Постоянный случайный секрет, `generateValue: true` в Render |
| `DATA_FILE` | `/tmp/lovelab/data.json` — локальный временный файл, без отдельного диска |
| `DISABLE_PAYWALL` | `false` — после бесплатной подготовки показываются тарифы и демонстрационная форма оплаты |
| `STRIPE_SECRET_KEY` | Пусто, не требуется |
| `VITE_PAYMENT_MODE` | `mock` — интерфейс явно сообщает, что оплата имитируется и списания нет |
| `LLM_API_KEY` | Только в серверных секретах; пусто для offline mock |
| `LLM_PROVIDER` | `anthropic` для Claude |
| `VITE_LLM_MODE` | `anthropic`, `mock` или `unknown`, в соответствии с реальным серверным режимом |
| `STATIC_DIR` | `/app/frontend`, уже задано в образе |
| `PORT` | Устанавливает хостинг; сервер использует его, если `ADDR` не задан |
| `FRONTEND_URL` | На Render можно не задавать; на другом хостинге — точный публичный HTTPS-origin |
| `FUNNEL` | `full` — начальная оценка, история, три коротких вопроса, репетиция и финальная оценка |
| `FREE_TURNS` | `5` — начальная оценка и история плюс три вопроса до подписки |
| `ENABLE_REHEARSAL` | `true` — выбор и редактирование первой фразы |

Секреты не передаются через `VITE_*`, Docker build args, URL или исходники. Ключ Claude нужен только серверу. **Бесплатный хостинг не делает вызовы Claude бесплатными:** они оплачиваются провайдеру по использованию. Чтобы не было вообще никаких расходов на модель, оставьте ключ пустым; ответы будут шаблонными, а не сгенерированными Claude.

## Демонстрационная оплата

Форма `/checkout/demo` открывается поверх затемнённого итога выбранного тарифа: диалог по центру на компьютере и нижняя панель на телефоне. Она использует локальный mock-провайдер, учётная запись Stripe не нужна. Поля уже заполнены тестовыми значениями, их можно редактировать:

| Поле | Тестовое значение |
| --- | --- |
| Номер карты | `4242 4242 4242 4242` |
| Имя на карте | Любое непустое тестовое имя, например `Demo User` |
| Срок действия | По умолчанию декабрь через три года; принимается текущий или будущий месяц в формате `MM/YY` |
| CVC | Любые три цифры, например `123` |

Кнопка `Pay` показывает цену выбранного тарифа. После подтверждения выбранный план становится активным для пары. Деньги не списываются, автоматических списаний и банковской операции нет. Не вводите настоящие реквизиты: форма принимает тестовый номер. Значения полей карты и имени остаются только в памяти страницы, не отправляются на сервер и не сохраняются в localStorage/sessionStorage. Запрос подтверждения передаёт только ID платёжной сессии; сервер проверяет её принадлежность текущей паре.

Если проект уже развёрнут с полным доступом без оплаты:

1. Отправьте обновления проекта в GitHub и дождитесь синхронизации Blueprint.
2. В **сервис → Environment** проверьте `DISABLE_PAYWALL=false`, `VITE_PAYMENT_MODE=mock`, `FUNNEL=full`, `FREE_TURNS=5`, `ENABLE_REHEARSAL=true`, пустой `STRIPE_SECRET_KEY`. API-ключ Claude менять не требуется.
3. При ручном изменении этих настроек выберите **Save, rebuild, and deploy**. Для `VITE_PAYMENT_MODE` нужна именно пересборка интерфейса.
4. Проверьте сценарий в новом профиле браузера или новой сессии инкогнито. Пара с уже активной подпиской повторно оплату не проходит. Прежний режим `DISABLE_PAYWALL=true` сам по себе не создавал сохранённую платную подписку.

Для необязательного режима полного доступа без формы можно вернуть `DISABLE_PAYWALL=true` и `VITE_PAYMENT_MODE=disabled`, затем пересобрать и развернуть приложение.

## Cloudflare Quick Tunnel: показ с вашего компьютера

1. Установите [cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/). Аккаунт Cloudflare и собственный домен для Quick Tunnel не нужны.
2. Соберите приложение из корня проекта:

```sh
VITE_PAYMENT_MODE=mock VITE_LLM_MODE=anthropic npm --prefix frontend run build
make build
make prepare-deploy
```

Если собираете offline mock, используйте `VITE_LLM_MODE=mock`. В локальном `.env.deploy` уже есть `SESSION_SECRET`; добавьте новый серверный ключ, если нужен Claude.

3. Запустите туннель в отдельном терминале и оставьте его работать:

```sh
cloudflared tunnel --url http://localhost:8080
```

Скопируйте выданный HTTPS-origin, например `https://your-random-name.trycloudflare.com`. Пока сервер не запущен, туннель может показывать ошибку соединения — это нормально.

4. В терминале приложения загрузите локальные секреты и запустите собранный сервер, подставив **реальный адрес туннеля**:

```sh
set -a
. ./.env.deploy
set +a
APP_ENV=production COOKIE_SECURE=true \
  FRONTEND_URL=https://your-random-name.trycloudflare.com \
  ALLOWED_ORIGINS=https://your-random-name.trycloudflare.com \
  ADDR=127.0.0.1:8080 STATIC_DIR=frontend/dist \
  DATA_FILE=data/judges.json DISABLE_PAYWALL=false STRIPE_SECRET_KEY= \
  FUNNEL=full FREE_TURNS=5 ENABLE_REHEARSAL=true \
  ./bin/lovelab
```

5. Передайте судьям адрес туннеля. Браузер работает через публичный HTTPS, cookie остаются Secure. Файл `data/judges.json` сохраняется на вашем компьютере и исключён из Git. При новом адресе туннеля обновите `FRONTEND_URL` и `ALLOWED_ORIGINS` и перезапустите сервер.

Ссылка перестаёт работать при остановке `cloudflared`. Не закрывайте ноутбук и не допускайте перехода в сон во время оценки. Quick Tunnel не предоставляет гарантии доступности. Незавершённые разговоры приложение не записывает на диск даже на локальном компьютере; завершённые результаты и профили сохраняются.

## Проверка перед отправкой судьям

- Корень сайта и `/healthz` открываются по HTTPS; прямые ссылки на страницы React работают.
- После истории и трёх коротких вопросов доступны личный инсайт, превью двух первых фраз и выбор тарифа. Затем открывается заранее заполненная форма тестовой карты. До подтверждения полный доступ закрыт.
- Карта `4242 4242 4242 4242`, тестовое имя, текущий или будущий месяц и трёхзначный CVC активируют план без списания денег; после этого можно закончить подготовку и открыть личный разбор.
- Неверные или пустые поля не активируют план. Возврат на страницу тарифов и повторное открытие checkout сохраняют выбранный ожидающий план.
- A получает приглашение B. B проходит свою подготовку в другом браузере или приватном окне.
- Оба видят общий журнал и могут поставить оценки; личные ответы и результаты остаются приватными.
- Анкета личности, профиль и повторный раунд доступны.
- В логах и Git нет секретов, cookie и текстов разговоров.

Локальные проверки:

```sh
make secret-check
make check
npm --prefix frontend run typecheck
npm --prefix frontend run lint
npm --prefix frontend run build
npm --prefix frontend run test:e2e
npm --prefix frontend run test:e2e:v2
```

`compose.yaml` остаётся дополнительным вариантом для уже имеющегося сервера с Docker и доменом; по умолчанию в нём тоже используется демонстрационная форма оплаты. Если `.env.deploy` был создан ранее, задайте в нём `VITE_PAYMENT_MODE=mock` и `DISABLE_PAYWALL=false` перед пересборкой: существующий файл не перезаписывается автоматически. Для бесплатного Render Compose не нужен: используется только `Dockerfile` и `render.yaml`.

Внутренние имена cookie, файлов данных и существующего Render-сервиса сохранены ради совместимости. Публичное название приложения — **Kintsugi**.
