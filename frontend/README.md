# Kintsugi — интерфейс

Веб-приложение на React и TypeScript в отдельной папке. Интерфейс на английском, инструкции на русском. Интерфейс использует синий градиент на основе `#273651`, золотистые акценты `#F0A04B`, светлый текст и розовую сакуру, как в презентации. Заголовки используют системный шрифт с засечками, основной текст — локальный Inter. Во время подготовки камера движется по SVG-ветке к текущему этапу, пройденные этапы раскрываются цветами, карточки вопросов плавно сменяются. При Back камера возвращается назад. Настройка `prefers-reduced-motion` отключает движение. Рисунки создаются локально из SVG, внешние сервисы и картинки не требуются. Макеты адаптируются к ширине браузера.

Bricolage Grotesque для логотипа и Inter для текста загружаются из `public/fonts/`, без запросов к Google Fonts. Лицензии OFL находятся рядом с файлами шрифтов. Исходный HTML-прототип остаётся локальным материалом; приложение использует существующие API, а не демонстрационные данные прототипа.

## Личное пространство

- `/journal` — ваши текущие и предыдущие разговоры, продолжение подготовки, личные итоги и кнопка **New conversation**. Список приходит из `GET /fight-sessions` и доступен без подписки. Общие оценки и подробности записи по-прежнему загружаются через `/journal`.
- `/partner` — фактический статус подготовки партнёра к текущему разговору: ещё не начал, готовится или готов. Статус обновляется каждые 15 секунд на видимой вкладке и по кнопке. Процент прохождения API не предоставляет; личные ответы партнёра не загружаются.
- `/home` — **My space**: ссылки на журнал и личные разделы, ваши сильные стороны и рекомендации по тесту About me, а также общие тенденции разговоров. Пока тест не пройден, вместо паттернов показана кнопка перехода к нему. Старый `/stats` перенаправляет на `/home`.
- `/profile` — сохранённая информация именно о вас: ответы знакомства, состояние теста, общий план и настройки данных. Отсутствующие возраст и другие необязательные сведения не подставляются. Переключение страниц не меняет роль браузера.
- После трёх коротких вопросов идут отдельные экраны инсайта и превью первой фразы, затем компактный выбор тарифа. Подробный личный разбор доступен дополнительно: названия тем и пояснения открыты, практические шаги закрыты до подписки. Равные секторы обозначают темы разговора, а не измеренные проценты личности.
- `/checkout/demo` — заранее заполненная форма тестовой карты в модальном окне (на мобильном — нижняя панель). Оплата имитируется локально, после подтверждения план становится активным для пары; реальные реквизиты не нужны. Escape и Cancel возвращают к незавершённой оплате.
- Личный список разговоров не скрывается за оплатой. Полные общие итоги, оценки и статистика по-прежнему проверяют право доступа на сервере.

Активный план сохраняется для следующих разговоров: повторно выбирать тариф или вводить тестовую карту не нужно. **New conversation** доступна, когда ваша текущая подготовка завершена или закрыта, а партнёр не занят своей подготовкой. Новый разговор создаёт новый токен приглашения; предыдущая ссылка сразу перестаёт действовать. Скопировать новую ссылку можно после завершения подготовки инициатора. Партнёр B готовится в текущем разговоре пары, а не создаёт отдельный раунд.

## Тарифы

- **Premium**: $199 в год, выбран по умолчанию. Помесячного варианта нет.
- **Kintsugi**: $19.99 в месяц за пару. Подпись показывает $9.99 на человека; сумма в checkout — $19.99 за двоих.
- **Date Night**: самостоятельный разовый план за $69.

Выбирается ровно один `plan`; одновременный выбор предложений и сложение цен не используются. Сервер возвращает `amountUsd` — цену выбранного плана. Новые запросы не отправляют `addOns`; непустое значение отклоняется. Для старой незавершённой комбинированной покупки интерфейс предлагает выбрать один текущий план и получить новый checkout; старый ID после замены больше не подтверждается. Уже активный доступ сохраняется и действует на будущие разговоры. Старые тарифы `program` и `premium_monthly` не предлагаются для новых покупок; они сохраняются для существующего доступа и восстановления прежней оплаты одного тарифа. Для старого `program` остаётся цена $149. Описания Date Night и SOS в тарифах не означают добавления отдельных новых страниц или API-сценариев.

## Быстрый старт

Полный список системных инструментов и команда установки всех зависимостей `make setup` находятся в [корневом README](../README.md#все-необходимые-инструменты).

Нужны Node.js 22.13+ в ветке 22 или 24+ (рекомендуется 24) и Go из корневого `go.mod`. Из корня проекта запустите API без обращения к внешним провайдерам:

```sh
FUNNEL=full FREE_TURNS=5 ENABLE_REHEARSAL=true DISABLE_PAYWALL=false \
LLM_API_KEY= LLM_PROVIDER= LLM_MODEL= LLM_BASE_URL= STRIPE_SECRET_KEY= make run
```

В другом терминале:

```sh
cd frontend
npm ci
VITE_LLM_MODE=mock VITE_PAYMENT_MODE=mock npm run dev
```

Откройте **http://localhost:5173**. Не заменяйте `localhost` на `127.0.0.1` в адресной строке: cookie, CORS и приглашения должны использовать один hostname. Если порт 5173 занят, остановите свой старый frontend-процесс; Vite не переключается незаметно на другой порт.

Для генерации через настроенный API-ключ запустите Go командой `make run-env` из корня. Затем запустите frontend с соответствующим `VITE_LLM_MODE=anthropic` или `openai`. Режим оплаты задаётся отдельно. `make run` не загружает `.env`, но наследует экспортированные переменные, поэтому ключи в демонстрационной команде явно очищены.

## Что можно проверить

1. Выберите начало подготовки на главной странице. Пройдите четыре коротких шага: имя партнёра и статус отношений, привычный способ реагировать, что помогает после ссоры, источник знакомства с Kintsugi.
2. Пройдите необязательный профиль из 20 утверждений или сразу начните разговор.
3. Оцените интенсивность ползунком 1–10, опишите ситуацию и ответьте на три коротких вопроса. Карточки расположены одна под другой; выбор можно изменить до нажатия Next. Свой текст ограничен 300 кодовыми точками Unicode. Инсайт и превью первой фразы открываются до выбора плана.
4. Выберите тариф. В режиме mock откроется `/checkout/demo`: `4242 4242 4242 4242`, имя `Demo User`, будущий месяц в формате `MM/YY` и CVC `123` уже заполнены. При желании измените тестовые значения и нажмите Pay. После подтверждения подписка станет активной и можно продолжить тот же разговор. Это имитация без списания денег; значения полей остаются только в памяти браузера, сервер получает лишь ID checkout.
5. Подтвердите готовность и скопируйте приглашение партнёру. Откройте ссылку в отдельном профиле/приватном окне, заполните три вопроса и завершите подготовку B.
6. Оба партнёра могут оценить разговор. Журнал показывает отдельную запись и среднюю оценку после двух ответов. Откройте запись на `/journal/:recordId`: общая тема, даты и оценки находятся отдельно от вашего личного итога. Check in открывает оценку этой записи. Если `myResult` отсутствует (`null`), общие сведения остаются доступны.
7. При серверном `ENABLE_CHECKPOINTS=true` в полной подготовке появляется промежуточный итог. Continue продолжает вопросы, Wrap up ведёт к финальным шагам. Проверьте обе ветки, перезагрузку на checkpoint, Back и Skip. Wrap up не заменяет явного подтверждения готовности.
8. В журнале создайте следующий разговор: оплаченная пара должна сразу попасть в подготовку. Предыдущий разговор остаётся в истории; после завершения нового появляется новая ссылка, а старая возвращает ошибку недоступности. Проверьте статус партнёра с обеих сторон, кнопку About me до теста, реальные паттерны после него и личные сведения в My profile.
9. Проверьте пустой журнал, настройки и удаление данных пары. Для сохранения завершённых результатов после перезапуска задайте серверу `DATA_FILE` и постоянный `SESSION_SECRET`; незавершённая подготовка на диск не сохраняется.

Без переменных окружения сервер использует прежний `FUNNEL=short`: термометр, факты, чувства, потребности и готовность. `FUNNEL=full` добавляет взгляд партнёра и финальный термометр; `ENABLE_REHEARSAL=true` добавляет репетицию. Пример окружения и Render используют `FUNNEL=full FREE_TURNS=5 ENABLE_REHEARSAL=true` для сценария прототипа. Интерфейс следует серверному этапу. В short-итоге показана только начальная интенсивность: `thermometerEnd: null` не превращается в ноль или фиктивное сравнение.

Чтобы проверить размытые закрытые разделы и форму демонстрационной оплаты, используйте пару без активной подписки и `DISABLE_PAYWALL=false`. При отключённом пейволе или активном доступе показывается обычный интерфейс. Для повторного показа оплаты начните с новой пары в другом профиле браузера. На уже работающем Render задайте `DISABLE_PAYWALL=false`, `VITE_PAYMENT_MODE=mock`, `FUNNEL=full`, `FREE_TURNS=5`, `ENABLE_REHEARSAL=true`, очистите `STRIPE_SECRET_KEY` и выберите **Save, rebuild, and deploy**: переменная `VITE_*` применяется при сборке.

В короткой полной подготовке checkpoint появляется после `feelings`; в длинной — после `needs`, а второй после `partner_view` только при включённой репетиции. На бесплатном тизере checkpoints отсутствуют. Чтобы проверить их сразу без оплаты, используйте серверные `ENABLE_CHECKPOINTS=true DISABLE_PAYWALL=true`; эти параметры не задаются через `VITE_*`.

## Окружение

При необходимости скопируйте `.env.example` в `.env.local` **в этой папке** и отредактируйте публичные параметры:

| Параметр | Назначение |
| --- | --- |
| `VITE_API_ORIGIN` | В разработке по умолчанию `http://localhost:8080`; в production-сборке по умолчанию тот же origin. Пустое значение также означает тот же origin. Без `/api/v1` в конце |
| `VITE_LLM_MODE` | `unknown`, `mock`, `openai`, `anthropic`; подпись режима и пояснение об обработке данных |
| `VITE_PAYMENT_MODE` | `mock` для демонстрационной формы карты (`DISABLE_PAYWALL=false`, пустой `STRIPE_SECRET_KEY`); `disabled` для полного доступа без формы (`DISABLE_PAYWALL=true`). Также поддерживаются `unknown` и `stripe_test` |

Параметры режима не переключают Go и не открывают платный доступ. Сверяйте их с серверным логом `llm_mode`/`payment_mode`. Для локального запуска серверные секреты задаются в корневом `.env`; на Render — в переменных окружения сервиса в разделе **Environment**. Локальный `.env` туда автоматически не загружается; ключ модели задаётся как `LLM_API_KEY`. Никаких API-ключей в `VITE_*`. API не сообщает текущие `FUNNEL` и `DATA_FILE`: этапы берутся из ответа сервера, а пояснение о сохранении в настройках описывает оба возможных режима.

## Сборка и проверки

```sh
npm run api:generate
npm run typecheck
npm run lint
npm run build
npx playwright install chromium
npm run test:e2e
npm run test:e2e:v2
```

API-типы генерируются из `../docs/features/backend-mvp/OPENAPI.yaml`. Браузерные наборы запускают свои серверы:

| Команда | Режим | Порты API / Vite |
| --- | --- | --- |
| `npm run test:e2e` | Сценарии `FUNNEL=full`, пейвол включён, checkpoints выключены; включает знакомство, репетицию и форму mock-оплаты | `18080` / `5174` |
| `npm run test:e2e:v2` | `FUNNEL=short`, checkpoints включены, пейвол отключён; промежуточные итоги и просмотр истории | `18082` / `5176` |

Оба набора явно очищают внешние ключи, используют mock-провайдеры, синтетические ответы и пустой `DATA_FILE`. A и B работают в разных BrowserContext. Не запускайте на этих портах пользовательские серверы одновременно с тестами. Артефакты тестов исключены из Git.

Автоматические проверки включают TypeScript, ESLint, production-сборку, `go test -race ./...`, `go vet ./...` и браузерные сценарии. Они покрывают путь A/B с оплатой, повторные разговоры без повторной оплаты, новые приглашения, текущие и прошлые итоги, About me и паттерны, личные сведения и статусы партнёра. Также проверяются восстановление после ошибок и перезагрузки, Back/Skip, приватная остановка, голосовой ввод, анимации и уменьшение движения, адаптация до 320 px и отсутствие отправки реквизитов тестовой карты на сервер. Набор v2 проверяет промежуточные итоги, лимит Unicode, короткую воронку и приватность истории A/B. Живые вызовы LLM и Stripe в эти проверки не входят.

Сборка создаётся в `dist/`. Для просмотра собранного интерфейса на согласованном origin используйте `npm run preview -- --port 5173`. При размещении нужны HTTPS, fallback на `index.html` для клиентских маршрутов и корректный origin API. Запросы `/api` нельзя направлять в HTML fallback или кэшировать.

## Ограничения начальной версии

- Без `DATA_FILE` данные бэкенда хранятся только в памяти. С ним сохраняются профили, результаты теста, активные подписки, завершённые личные итоги и журнал; для сохранения доступа нужен постоянный `SESSION_SECRET`. Незавершённые подготовки не сохраняются. Регистрации и восстановления аккаунта нет.
- Старый URL незавершённой подготовки после перезапуска может вернуть `404`, а `/couples/me` — `currentSessionId: null`. Вернитесь на главную: возможность нового старта определяет сервер. Использованный бесплатный тизер остаётся использованным, поэтому повторный старт A потребует полного доступа (`402`). B может начать свою часть заново, если результат A сохранился; статус B до этого может оставаться `in_progress`.
- Известная ошибка бэкенда: ожидающий подтверждения mock-checkout из `DATA_FILE` после перезапуска не подтверждается (`409 payment_unconfirmed`), поскольку состояние мока не восстановлено. Повтор из интерфейса не исправляет это; уже активные подписки продолжают работать.
- Реальный LLM и Stripe test запускаются отдельно; стандартные браузерные тесты не подтверждают доступность внешней модели/аккаунта.
- Сетевой сбой генерации приводит к сверке сохранённой сессии и ручному повтору. Все вызовы генерации одного действия ограничены общим сроком 25 секунд; при таймауте ответ не считается сохранённым, пока состояние не подтверждено API.
- Продление/отмена Stripe-подписки и обновление истёкшего checkout ещё не реализованы. Удаление данных приложения не отменяет подписку.
- В первой версии нет offline-очереди, аналитики, доставки приглашений и push-уведомлений. Пользователь сам передаёт ссылку партнёру.
- На стороне браузера сырые ответы и личные результаты живут только в памяти; они не записываются в localStorage/sessionStorage. Запросы личных данных разделены по паре и роли. В sessionStorage сохраняются только указатели возвращения из оплаты. На сервере завершённые итоги могут сохраняться в `DATA_FILE`; сырые ответы не записываются на диск.
