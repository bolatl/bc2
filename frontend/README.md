# Love Lab — интерфейс

Веб-приложение на React и TypeScript в отдельной папке. Интерфейс на английском, инструкции на русском. Интерфейс использует синий градиент на основе `#273651`, золотистые акценты `#F0A04B`, светлый текст и розовую сакуру, как в презентации. Заголовки используют системный шрифт с засечками, основной текст — локальный Inter. Во время подготовки камера движется по SVG-ветке к текущему этапу, пройденные этапы раскрываются цветами, карточки вопросов плавно сменяются. При Back камера возвращается назад. Настройка `prefers-reduced-motion` отключает движение. Рисунки создаются локально из SVG, внешние сервисы и картинки не требуются. Макеты адаптируются к ширине браузера.

Bricolage Grotesque для логотипа и Inter для текста загружаются из `public/fonts/`, без запросов к Google Fonts. Лицензии OFL находятся рядом с файлами шрифтов. Исходный HTML-прототип остаётся локальным материалом; приложение использует существующие API, а не демонстрационные данные прототипа.

## Личное пространство

- `/home` — текущая подготовка, свой итог и готовность пары.
- `/partner` — приглашение, общий этап подготовки партнёра и совместный журнал. Статус обновляется каждые 15 секунд на видимой вкладке и по кнопке. Процент прохождения API не предоставляет; личные ответы партнёра не загружаются.
- `/profile` — ваша рефлексия, состояние общего плана и настройки данных. Переключение видов не меняет роль браузера.
- На экране подписки слева — диаграмма личного разбора, справа — единый блок тарифов. Названия 3–5 тем и их объяснения видны; практические шаги закрыты размытыми заглушками. Сервер не передаёт закрытый текст в DOM. Равные секторы обозначают темы разговора, а не измеренные проценты личности.
- Другие закрытые разделы показаны размытым декоративным превью. API продолжает проверять доступ, кнопки подписки остаются чёткими и доступными с клавиатуры.

## Быстрый старт

Полный список системных инструментов и команда установки всех зависимостей `make setup` находятся в [корневом README](../README.md#все-необходимые-инструменты).

Нужны Node.js 22.13+ в ветке 22 или 24+ (рекомендуется 24) и Go из корневого `go.mod`. Из корня проекта запустите API без обращения к внешним провайдерам:

```sh
LLM_API_KEY= LLM_PROVIDER= LLM_MODEL= LLM_BASE_URL= STRIPE_SECRET_KEY= make run
```

В другом терминале:

```sh
cd frontend
npm ci
VITE_LLM_MODE=mock VITE_PAYMENT_MODE=mock npm run dev
```

Откройте **http://localhost:5173**. Не заменяйте `localhost` на `127.0.0.1` в адресной строке: cookie, CORS и приглашения должны использовать один hostname. Если порт 5173 занят, остановите свой старый frontend-процесс; Vite не переключается незаметно на другой порт.

Для генерации через настроенный API-ключ запустите Go командой `make run-env` из корня. Затем запустите frontend с соответствующим `VITE_LLM_MODE=anthropic` или `openai`. Режим оплаты задаётся отдельно. `make run` не загружает `.env`, но наследует экспортированные переменные, поэтому ключи в демонстрационной команде явно очищены.

## Что можно проверить

1. Нажмите Get started и ответьте на восемь вопросов анкеты.
2. Пройдите необязательный профиль из 20 утверждений или сразу начните разговор.
3. Опишите свою ситуацию свободным текстом и проверьте, что следующие вопросы используют её контекст. Выберите интенсивность, отвечайте карточками или собственным текстом до 300 кодовых точек Unicode. Счётчик одинаково ограничивает отправку кнопкой и Enter; Shift+Enter вставляет перенос. На бесплатном лимите появится предварительный итог и выбор плана.
4. В режиме mock оплата проходит без платёжных данных. После подтверждения откроется тот же разговор.
5. Подтвердите готовность и скопируйте приглашение партнёру. Откройте ссылку в отдельном профиле/приватном окне, заполните три вопроса и завершите подготовку B.
6. Оба партнёра могут оценить разговор. Журнал показывает отдельную запись и среднюю оценку после двух ответов. Откройте запись на `/journal/:recordId`: общая тема, даты и оценки находятся отдельно от вашего личного итога. Check in открывает оценку этой записи. Если `myResult` отсутствует (`null`), общие сведения остаются доступны.
7. При серверном `ENABLE_CHECKPOINTS=true` в полной подготовке появляется промежуточный итог. Continue продолжает вопросы, Wrap up ведёт к финальным шагам. Проверьте обе ветки, перезагрузку на checkpoint, Back и Skip. Wrap up не заменяет явного подтверждения готовности.
8. Проверьте пустой журнал, настройки и удаление данных пары. Для сохранения завершённых результатов после перезапуска задайте серверу `DATA_FILE` и постоянный `SESSION_SECRET`; незавершённая подготовка на диск не сохраняется.

По умолчанию сервер использует `FUNNEL=short`: термометр, факты, чувства, потребности и готовность. `FUNNEL=full` добавляет взгляд партнёра и финальный термометр; `ENABLE_REHEARSAL=true` добавляет репетицию. Интерфейс следует серверному этапу, а боковая навигация не предполагает обязательные семь шагов. В short-итоге показана только начальная интенсивность: `thermometerEnd: null` не превращается в ноль или фиктивное сравнение.

Чтобы проверить размытые закрытые разделы, используйте пару без активной подписки и `DISABLE_PAYWALL=false`. При отключённом пейволе или активном доступе показывается обычный интерфейс.

В короткой полной подготовке checkpoint появляется после `feelings`; в длинной — после `needs`, а второй после `partner_view` только при включённой репетиции. На бесплатном тизере checkpoints отсутствуют. Чтобы проверить их сразу без оплаты, используйте серверные `ENABLE_CHECKPOINTS=true DISABLE_PAYWALL=true`; эти параметры не задаются через `VITE_*`.

## Окружение

При необходимости скопируйте `.env.example` в `.env.local` **в этой папке** и отредактируйте публичные параметры:

| Параметр | Назначение |
| --- | --- |
| `VITE_API_ORIGIN` | В разработке по умолчанию `http://localhost:8080`; в production-сборке по умолчанию тот же origin. Пустое значение также означает тот же origin. Без `/api/v1` в конце |
| `VITE_LLM_MODE` | `unknown`, `mock`, `openai`, `anthropic`; подпись режима и пояснение об обработке данных |
| `VITE_PAYMENT_MODE` | `unknown`, `mock`, `stripe_test`, `disabled`; для демонстрации без оплаты используйте `disabled` вместе с серверным `DISABLE_PAYWALL=true` |

Параметры режима не переключают Go и не открывают платный доступ. Сверяйте их с серверным логом `llm_mode`/`payment_mode`. Секреты провайдера/Stripe/сессии остаются в корневом `.env`; никаких API-ключей в `VITE_*`. API не сообщает текущие `FUNNEL` и `DATA_FILE`: этапы берутся из ответа сервера, а пояснение о сохранении в настройках описывает оба возможных режима.

## Сборка и проверки

```sh
npm run api:generate
npm run typecheck
npm run lint
npm run build
npx playwright install chromium
npm run test:e2e
npm run test:e2e:v2
```

API-типы генерируются из `../docs/features/backend-mvp/OPENAPI.yaml`. Браузерные наборы запускают свои серверы:

| Команда | Режим | Порты API / Vite |
| --- | --- | --- |
| `npm run test:e2e` | Десять сценариев `FUNNEL=full`, пейвол включён, checkpoints выключены | `18080` / `5174` |
| `npm run test:e2e:v2` | `FUNNEL=short`, checkpoints включены, пейвол отключён; промежуточные итоги и просмотр истории | `18082` / `5176` |

Оба набора явно очищают внешние ключи, используют mock-провайдеры, синтетические ответы и пустой `DATA_FILE`. A и B работают в разных BrowserContext. Не запускайте на этих портах пользовательские серверы одновременно с тестами. Артефакты тестов исключены из Git.

Пройдены TypeScript-проверка, ESLint, production-сборка, `go test -race ./...`, `go vet ./...` и все 15 браузерных тестов. Шесть основных сценариев покрывают путь A/B с оплатой и удалением, восстановление после 503/перезагрузки, Back/Skip, safety, адаптацию и анкеты/Mini-IPIP. Три сценария дизайна проверяют движение по ветке и анимацию карточки, уменьшение движения, страницы своего профиля и партнёра, адаптацию до 320 px, размытые превью и открытие доступа через mock-checkout. Отдельный сценарий проверяет контекстные вопросы, открытые пояснения диаграммы и открытие практических рекомендаций после оплаты. Пять сценариев v2 проверяют checkpoint (Continue, Wrap up, Back, Skip, перезагрузка и повтор после ошибки), 300 кодовых точек Unicode, короткий итог без финального термометра и приватность истории A/B, включая пустой итог и чужую пару. Новые экраны проверены на настольной и мобильной ширине. Живые вызовы LLM и Stripe в эти проверки не входят.

Сборка создаётся в `dist/`. Для просмотра собранного интерфейса на согласованном origin используйте `npm run preview -- --port 5173`. При размещении нужны HTTPS, fallback на `index.html` для клиентских маршрутов и корректный origin API. Запросы `/api` нельзя направлять в HTML fallback или кэшировать.

## Ограничения начальной версии

- Без `DATA_FILE` данные бэкенда хранятся только в памяти. С ним сохраняются профили, результаты теста, активные подписки, завершённые личные итоги и журнал; для сохранения доступа нужен постоянный `SESSION_SECRET`. Незавершённые подготовки не сохраняются. Регистрации и восстановления аккаунта нет.
- Старый URL незавершённой подготовки после перезапуска может вернуть `404`, а `/couples/me` — `currentSessionId: null`. Вернитесь на главную: возможность нового старта определяет сервер. Использованный бесплатный тизер остаётся использованным, поэтому повторный старт A потребует полного доступа (`402`). B может начать свою часть заново, если результат A сохранился; статус B до этого может оставаться `in_progress`.
- Известная ошибка бэкенда: ожидающий подтверждения mock-checkout из `DATA_FILE` после перезапуска не подтверждается (`409 payment_unconfirmed`), поскольку состояние мока не восстановлено. Повтор из интерфейса не исправляет это; уже активные подписки продолжают работать.
- Реальный LLM и Stripe test запускаются отдельно; стандартные браузерные тесты не подтверждают доступность внешней модели/аккаунта.
- Сетевой сбой генерации приводит к сверке сохранённой сессии и ручному повтору. Все вызовы генерации одного действия ограничены общим сроком 25 секунд; при таймауте ответ не считается сохранённым, пока состояние не подтверждено API.
- Продление/отмена Stripe-подписки и обновление истёкшего checkout ещё не реализованы. Удаление данных приложения не отменяет подписку.
- В первой версии нет offline-очереди, аналитики, доставки приглашений и push-уведомлений. Пользователь сам передаёт ссылку партнёру.
- На стороне браузера сырые ответы и личные результаты живут только в памяти; они не записываются в localStorage/sessionStorage. Запросы личных данных разделены по паре и роли. В sessionStorage сохраняются только указатели возвращения из оплаты. На сервере завершённые итоги могут сохраняться в `DATA_FILE`; сырые ответы не записываются на диск.
