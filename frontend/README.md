# Love Lab — интерфейс

Начальная версия на React и TypeScript в отдельной папке. Интерфейс на английском, инструкции на русском. Белая поверхность, одна гарнитура и синий акцент следуют Swiss-направлению из `frontend.md`.

## Быстрый старт

Нужны Node.js 22.13+ в ветке 22 или 24+ (рекомендуется 24) и Go из корневого `go.mod`. Из корня проекта запустите API без обращения к внешним провайдерам:

```sh
LLM_API_KEY= LLM_PROVIDER= LLM_MODEL= LLM_BASE_URL= STRIPE_SECRET_KEY= make run
```

В другом терминале:

```sh
cd frontend
npm ci
VITE_LLM_MODE=mock VITE_PAYMENT_MODE=mock npm run dev
```

Откройте **http://localhost:5173**. Не заменяйте `localhost` на `127.0.0.1` в адресной строке: cookie, CORS и приглашения должны использовать один hostname. Если порт 5173 занят, остановите свой старый frontend-процесс; Vite не переключается незаметно на другой порт.

Для генерации через настроенный API-ключ запустите Go командой `make run-env` из корня. Затем запустите frontend с соответствующим `VITE_LLM_MODE=anthropic` или `openai`. Режим оплаты задаётся отдельно. `make run` не загружает `.env`, но наследует экспортированные переменные, поэтому ключи в демонстрационной команде явно очищены.

## Что можно проверить

1. Нажмите Get started и ответьте на восемь вопросов анкеты.
2. Пройдите необязательный профиль из 20 утверждений или сразу начните разговор.
3. Выберите интенсивность, отвечайте карточками или собственным текстом. На бесплатном лимите появится предварительный итог и выбор плана.
4. В режиме mock оплата проходит без платёжных данных. После подтверждения откроется тот же разговор.
5. Подтвердите готовность и скопируйте приглашение партнёру. Откройте ссылку в отдельном профиле/приватном окне, заполните три вопроса и завершите подготовку B.
6. Оба партнёра могут оценить разговор. Журнал показывает отдельную запись и среднюю оценку после двух ответов.
7. Проверьте перезагрузку страницы, Back, Skip, пустой журнал, настройки и удаление данных пары.

## Окружение

При необходимости скопируйте `.env.example` в `.env.local` **в этой папке** и отредактируйте публичные параметры:

| Параметр | Назначение |
| --- | --- |
| `VITE_API_ORIGIN` | По умолчанию `http://localhost:8080`; пустое значение — API на том же origin. Без `/api/v1` в конце |
| `VITE_LLM_MODE` | `unknown`, `mock`, `openai`, `anthropic`; подпись режима и пояснение об обработке данных |
| `VITE_PAYMENT_MODE` | `unknown`, `mock`, `stripe_test`; подпись режима оплаты |

Параметры режима не переключают Go и не открывают платный доступ. Сверяйте их с серверным логом `llm_mode`/`payment_mode`. Секреты провайдера/Stripe/сессии остаются в корневом `.env`; никаких API-ключей в `VITE_*`.

## Сборка и проверки

```sh
npm run api:generate
npm run typecheck
npm run lint
npm run build
npx playwright install chromium
npm run test:e2e
```

API-типы генерируются из `../docs/features/backend-mvp/OPENAPI.yaml`. Проверки браузера поднимают отдельный Go на 18080 и Vite на 5174, явно очищают внешние ключи и используют синтетические ответы. A и B работают в разных BrowserContext. Не запускайте на этих портах пользовательские серверы одновременно с тестами. Артефакты тестов исключены из Git.

Для начальной версии пройдены TypeScript-проверка, ESLint, production-сборка и все шесть Playwright-тестов в Chromium: полный путь A/B с оплатой и удалением, восстановление после 503/перезагрузки, Back/Skip, safety, адаптация и анкеты/Mini-IPIP. Дополнения Go проверены `go test -race ./...`, `go vet ./...` и валидатором контракта. Живые вызовы LLM и Stripe в эти проверки не входили.

Сборка создаётся в `dist/`. Для просмотра собранного интерфейса на согласованном origin используйте `npm run preview -- --port 5173`. При размещении нужны HTTPS, fallback на `index.html` для клиентских маршрутов и корректный origin API. Запросы `/api` нельзя направлять в HTML fallback или кэшировать.

## Ограничения начальной версии

- Бэкенд хранит данные в памяти; перезапуск завершает старые сессии. Регистрации и восстановления аккаунта нет.
- Реальный LLM и Stripe test запускаются отдельно; стандартные браузерные тесты не подтверждают доступность внешней модели/аккаунта.
- Сетевой сбой генерации приводит к сверке сохранённой сессии и ручному повтору. Общий серверный deadline и политика повторов Anthropic остаются задачами бэкенда.
- Продление/отмена Stripe-подписки и обновление истёкшего checkout ещё не реализованы. Удаление данных приложения не отменяет подписку.
- В первой версии нет offline-очереди, аналитики, доставки приглашений и push-уведомлений. Пользователь сам передаёт ссылку партнёру.
- Сырые ответы и личные результаты живут только в памяти страницы. В sessionStorage сохраняются только указатели возвращения из оплаты.
